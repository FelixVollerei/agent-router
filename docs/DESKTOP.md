# 需求工作台使用指南 · v0.3

双击桌面 **Model Router**。页面在默认浏览器打开，后台服务隐藏运行。

## 从一句需求开始

1. 在默认的「需求发布（简易）」中描述你想完成的事情，点击「研究并生成方案」。无需工作区、文件类型或权限表单。
2. 系统先拆解需求、比较实现路线，再核对可用资料，最后生成调度方案。预研分两轮，每轮有180秒上限；不用一直停留在当前页面。
3. 审阅方案中的研究结论、来源、假设、模型选择、完整任务 Prompt、拟修改文件、验收标准、权限和 Codex 插件建议。
4. 可以继续聊天，例如「改用纯前端，保留之前的筛选功能」，让它生成新版本；也可以直接编辑方案。
5. 点击「发布此方案」会先保存当前编辑，再使用选定模型执行。没有工程时自动创建独立工作目录。相同方案版本不会重复发布。

## 可选的资料和高级模式

「添加资料」支持最多8份文本文件，文本合计50000字。这些内容作为预研和执行资料；没有工程时也会放入独立工作目录。

需要处理现有工程时，切到高级模式，填写工程文件夹完整路径。项目名称、可修改范围、禁止范围、验收标准、调度偏好、检查命令、任务特征 JSON 均可选。工程内容只在用户主动提供路径后读取；预研从最多500个文件名中选择最多8份文本文件，每份最多读取6000字节。

现有 CLI 高级调度与自动升级流程继续可用。页面审阅发布固定使用所选模型，不在后台悄悄切换为其他执行模型；原有必需独立评审仍由策略决定。失败后可继续讨论，再发布新版本。

## 会话、版本和执行记录

左侧为需求会话，可搜索标题或项目名称，旧版任务仍显示为历史记录。每个会话保存用户讨论、生成方案、手工编辑版本和发布记录。方案内可切换历史版本查看；旧版只读，修改当前版不会改变已发布版本。

发布记录中的「查看具体执行记录」显示执行模型消息、文件操作、检查、差异和原始 Prompt；「打开成果文件夹」打开这一次执行的候选目录。无自动验收脚本的任务会标记「待人工验收」，成果仍可查看和使用。

新的 Codex 执行使用持久会话。记录中的「打开 Codex 会话」在本机 CLI 打开准确的会话 ID；不保证在 Codex 桌面侧栏中自动定位。旧版使用临时会话，可能无法恢复。DeepSeek Harness 的完整执行记录在本工作台内查看，没有伪造的外部跳转。

通过独立验证的结果可手动应用到源目录；页面会要求确认，并检查源目录及候选内容未发生变化。新项目的源目录是工作台管理的独立目录。

## 设置与实际能力

左下角「设置」包括模型连接、预算、检查命令和使用指南。

- DeepSeek 用于需求预研；每轮开启思考。API Key 可选择用 Windows DPAPI 加密保存，未保存时只在当前服务内存中使用。
- 未连接 DeepSeek 时生成标识为「基础模板」的可编辑方案，不冒充已完成模型预研。
- Codex 使用本机已登录账户。模型 ID 可在设置中修改。
- 当前预研没有实时网页搜索，只使用输入资料、可选工程文本和模型已有知识。来源与限制会列入方案。
- 方案包含建议权限和插件用途，但当前自动执行没有外部插件通道，不会自动安装、启用插件或访问相关账户。需要插件时可把完整 Prompt 带到已接入插件的 Codex 环境。
- 实际运行可读取候选工程，按范围写入；Codex 可在本机沙箱内执行命令，DeepSeek 使用受控文件工具与已配置检查。默认关闭执行网络访问，不自动部署或发布；模型 API 连接仍需要网络。

## 停止、关闭和重新打开

预研或执行期间使用输入框旁的「停止」。已开始的独立检查可能需要等当前有时限的操作结束。关闭浏览器不会停止后台工作。

退出服务在「设置」中进行，进行中的任务需先停止或结束。重启会保留会话和成果；意外中断不会自动重新发布任务。再次双击桌面图标可打开工作台。

## 本地保存位置

所有页面数据在 `%LOCALAPPDATA%\EngineeringModelRouter`：

- `conversations/`：会话、方案版本和发布关联，原子写入 JSON。
- `data/runs/`：执行消息、Prompt、检查、差异和候选文件。
- `sources/`：没有提供工程时创建的独立源目录。
- `settings.json`：不包含密钥的模型设置。
- `deepseek.dpapi`：可选的当前 Windows 账户加密密钥。

服务只监听127.0.0.1，接口使用令牌鉴权与同源检查，不会发布到互联网。桌面快捷方式重建命令：`python -B scripts/install_desktop.py`。

Codex 会话恢复参考：[官方 CLI 命令文档](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。
