# Agent Router 方案 v1（定版）

定版日期：2026-09-14。基线：v0.3.0 / `7c487c8`。本页的v1是方案版本；实现版本为v0.4.1，不宣称1.0稳定性或DSH Standard兼容认证。用户已授权在本轮实施Router；墨小汐随后已获授权实施PC适配，手机三项修复等用户回来。

## 1. 产品与交付范围

Router继续是可独立使用的需求研究和工程执行工作台，同时成为可被墨小汐调用的执行服务。保留原计划的模型发现、联网预研、评测选型和审阅发布四条主线，新增持久任务接口。CLI、桌面和宿主接口复用现有Policy、Orchestrator、Workspace、Verifier、Provider。

| 交付 | v1定版范围 | 完成依据 |
| --- | --- | --- |
| 模型目录 | 用户可配置provider、地址、凭据环境变量、模型和执行档位；按需查询兼容`/models`或Codex `model/list`；区分配置、发现、可执行和未知 | 自定义目录持久化、发现结果有来源/时间、失败不覆盖旧配置；发现不会自动授权/提升档位 |
| 联网预研 | 显式开启，使用用户指定的公开检索词及URL；可选Brave搜索，未配置搜索时仍可读取指定公开页面；结果附URL、采集时间、内容摘要/hash及失败原因 | 请求/页数/字节/时间有界，取消有效；页面和搜索片段分开，资料作为不可信证据进入两轮预研和最终方案 |
| 证据选型 | 结构化导入评测记录，核对精确provider/model/reasoning、任务类型、评测版本/量纲、时间及来源；结合既有风险/成本/经验策略 | 未审阅、过期、版本不匹配、不适用记录不影响排序；不混合不同量纲，不用排名解除风险或授权边界 |
| 宿主任务 | 无窗口stdio JSON-RPC、版本握手、持久接纳/状态/有序事件/取消/成果接口；单执行槽 | 同请求不重复执行、冲突明确拒绝；取消/超时/重启未知可核对；结果只在候选目录 |
| 授权与预算 | 宿主预配置workspace及读写/check/model允许范围；输入只引用workspace ID。授权文件包与原工程分开，累计执行尝试/执行器调用和总墙钟有界 | 拒绝范围扩大、缺上传许可、未配置命令、未声明预算；独立review计入执行器调用；不谎报token/远端计费硬限制 |
| 兼容与交付 | 保留旧CLI、桌面会话/审阅发布；增加可操作入口、示例及Python宿主client | 旧测试与新增跨进程fixture通过，独立原工程不变；真实模型/搜索凭据未配置时明确未测 |

本轮不引入任意插件执行、完整多Agent并发、自动发布/部署/推广、手机Runtime或新数据库服务；这些继续保留后续方向。采用Python标准库和现有SQLite/JSON，不增加Node运行时来复制标准框架。

## 2. 借鉴DSH Standard的范围

采用三个原则：连接只负责版本/调用生命周期；模型、任务、成果各自定义业务值；能力声明必须来自活实现，不能把安装或广告当授权。Router使用自己的`router.jobs/v1`协议，后续可增加单独标准adapter。内部代码不导入DSH或Cordis，墨小汐Core也不接触外部协议值。

DSH Standard目前是早期草案，connection参考代码与计划中的ConnectionService/Host SPI尚有差距；model协议也不定义账单、额度或远程推理。因此只借鉴边界与语义，不声称本版可直接连接所有DSH客户端。来源：[架构](https://github.com/Yan-Zero/dsh-std/blob/main/docs/architecture.md)、[connection现状](https://github.com/Yan-Zero/dsh-std/blob/main/packages/connection/README.md)、[model目录](https://github.com/Yan-Zero/dsh-std/blob/main/packages/model/README.md)（2026-09-14核对）。

## 3. 模型与研究决策

模型身份为`provider + model + reasoning`，产品逻辑ID另存。发现记录保存可选推理档、来源和时间，不臆测工具能力、价格或成功率。新模型经用户配置后进入策略，保留rank/成本/成功率为显式先验。执行器工具能力来自provider实现；不根据模型名猜测。Codex使用正式`model/list`分页；兼容API使用`GET /models`，两者不相互代替。[Codex](https://learn.chatgpt.com/docs/app-server)、[DeepSeek](https://api-docs.deepseek.com/api/list-models/)。

联网研究与执行网络权限分开。检索只发送本轮显式公开词，不自动上传全部会话/附件/工程。公开页面仅HTTP(S)中的HTTPS路径，拒绝私网/回环/本地文件、凭据URL和重定向；连接固定已校验IP并保留TLS主机验证。超时在独立worker外层约束，慢响应/解析不能无限占用前台。Brave是首个可选检索adapter，不是强制账号依赖；墨小汐未来可通过同结构证据包复用其现有搜索。[Brave接口](https://api-dashboard.search.brave.com/app/documentation/web-search/get-started)。

评测采用经用户审阅的结构化导入，支持从指定公开JSON源获取后核对；不通用抓取排行榜DOM或由LLM伪造分数。记录包括`benchmark/version/task_type/metric/score/min/max/higher_is_better/provider/model/reasoning/source_url/evaluated_at/reviewed`。只在同评测版本和量纲的可比候选间提供有上限的排序修正；本地经验和安全门槛仍保留。来源缺失/过期显示unknown，真实成本缺失为null，不填零或推导“已经省钱”。

## 4. Router宿主合同

传输为私有子进程stdin/stdout上的有界JSON-RPC 2.0（每行一个对象），stderr为诊断；不监听网络、不借用桌面随机HTTP端口。启动参数固定配置路径、状态目录和宿主client ID，秘密只来自宿主环境/既有凭据管理。只有持有该本地管道且被宿主启动策略允许的调用方可提交，不接受消息中的自报principal作为新授权。

| 方法 | 输入 / 结果 |
| --- | --- |
| `initialize` | 请求`protocol=router.jobs/v1`；返回server版本、真实features、预算强制级别、传输限制 |
| `catalog.list` | 当前配置与provider可观测状态；不触发模型执行 |
| `job.submit` | `client_task_id/idempotency_key/session_id/workspace_id/task/limits/allowed_models/upload_allowed`；持久化后返回`job_id/state` |
| `job.get` | job身份、状态、原因、映射与计量；断开后的查询不能触发执行 |
| `job.lookup`（v0.4.1增补） | 按`client_task_id`及启动client身份只读查询；丢失submit响应时找回job，返回found/job；无接纳、预算或执行副作用 |
| `job.events` | `job_id/after/limit`；返回持久sequence有序页，客户端以job+sequence去重 |
| `job.cancel` | 幂等提出取消；返回请求事实及本地停止/远端停止的不同字段 |
| `job.artifacts` | 候选diff、验证报告和成果文件的受控引用、相对路径、字节数和SHA256；不接受任意读取路径 |

稳定身份：调用请求ID只关联一次RPC响应；`client_task_id`关联墨小汐父任务；幂等键关联同一内容；`job_id`关联Router持久任务；`run_id`关联一次编排。相同幂等键/不同规范化内容拒绝；同父任务不能借换键重复执行。SQL事务先接纳再派发，单状态目录只有一个服务拥有执行权。最多单任务，不暗中排无限队列。

状态：`accepted → running → verified | needs_human | blocked | failed | cancelled | timed_out | unknown`，中间可见`cancel_requested`。verified只指候选检查通过，`applied=false`；needs_human为未验收终态，本版无原地签收/继续能力。服务恢复时未确认任务标unknown，不重派。正常断开请求停止自有工作；异常崩溃保留不确定性和执行槽隔离，不依据PID名称终止其他进程。

工作区在受信配置中注册。请求范围只能收紧配置；只导出被允许读取且有本轮上传许可的文件。输入manifest固定相对路径/hash，拒绝链接/穿越和源漂移。执行与检查都在包副本；写入范围由provider限制和最终Verifier共同核对。副本不是任意不可信shell的OS沙箱，Codex沿用原沙箱；可信检查命令可执行，其代码不得由模型篡改后冒充独立oracle。成果返回与正式应用分离，本版宿主接口不提供promote。

工程预算与墨小汐旧60秒/6000 token的资料读取合同分开：父任务传总秒数、最大尝试、最大执行器调用（含review）、允许模型集合，Router取宿主配置和父限制交集；review消耗同一父预算；执行器内部的多轮API请求不等于一次顶层调用。总时限覆盖打包、策略、执行和验证，取消在本地进程级监督。实际token/费用为可选观测，不宣称provider硬token限；无法满足要求的预算字段在接纳前拒绝，不能静默忽略。无自主执行授权。

## 5. 墨小汐接口与适配

墨小汐只增加可拔除的`AgentRouterBackend`、宿主连接client、工程任务profile与持久映射；继续通过Gate/TaskRuntime发起，Session/Memory/主对话ModelRouter仍由墨小汐管理。合同细节以墨小汐`docs/ARCHITECTURE.md`的AR-005定版节为准；PC单任务适配已实施并经独立生成工程验证；旧profile保留，详细验收见墨小汐P7增补及本项目VALIDATION。

完整流程：用户需求 → 墨小汐生成可审阅工程任务及授权资料 → 持久父预算/派发身份 → Router接纳 → 原编排与受控升级/review → 候选和真实检查 → 墨小汐同会话任务状态与有来源Observation。工程成果保留大文件引用，简短Observation不塞整份diff。墨小汐的显式本轮授权可以替代Router桌面“发布”动作，不重复要求点击两次。

## 6. 实施顺序与冻结规则

1. 先固定本方案及墨小汐适配合同；此后不把用户未取消的原路线图降成“只留接口”。
2. 实施目录/发现、联网证据、评测排序与桌面入口，保留原审阅发布。
3. 实施宿主持久任务、预算/包/取消/结果接口与Pythonclient示例；复用执行核心，关闭时原产品正常工作。
4. 跑旧回归、新增确定性合同与真实子进程fixture；记录精确版本、命令、结果和未测路径。功能测试不消耗真实模型额度。
5. 可用条件下做只读发现/公开资料探针；真实模型工程任务与墨小汐端到端验收分别记录，不以fixture冒充。原Router库写回前核对原文件未变化，只应用本轮文件。

宿主执行首版仅支持Windows，以Job Object约束worker及后代生命周期；无法建立约束时拒绝执行。`max_provider_calls`和结果`provider_calls`均计顶层执行器调用，不代表内部API次数。预算或模型超出宿主范围时接纳前拒绝，要求调用方明确收紧，不静默扩大。Codex的包外读隔离依赖CLI/OS沙箱，打包不等于证明隔离，启用前需单独验收。检查前拒绝越权候选，检查后再核对范围；复杂检查依赖的oracle文件必须登记`protected_files`。

方案定版不等于所有实现验收已通过。实施状态与原始验证统一维护在[VALIDATION](VALIDATION.md)，路线图只维护顺序与未完成项。
